# AI 分析流程与提示词说明（成迹 DoneTrace）

> 本文档与代码逐字对应，用于分析如何改善 AI 复盘质量。
> 更新日期：2026-10-30（v3：AI 回复语言按界面语言锁定（中/英提示词均明确要求）；任务清单与项目复盘记录发送给 AI 前按完成时间正序排列）
> 代码位置：
> - 提示词与上下文构造：`src-tauri/src/commands/ai.rs`
> - DeepSeek 请求客户端：`src-tauri/src/ai/mod.rs`
> - 周期数据收集：`src-tauri/src/commands/analysis.rs`
> - 工时折算（Rust 权威实现）：`src-tauri/src/scoring.rs` 的 `fmt_work_hours`
> - API 配置：`src-tauri/src/commands/settings.rs`
> - 前端触发入口：`src/pages/AnalysisPage.tsx`、`src/pages/ProjectDetailPage.tsx`

## 1. 总体流程

```
用户在界面点击「生成分析 / 重新分析 / 生成复盘」
        │
        ▼
Tauri command（Rust 侧）
        │
        ├─ 1. 读取设置：deepseek_api_key / base_url / model
        │     （默认 https://api.deepseek.com 与 deepseek-chat；无 Key 直接报错）
        ├─ 2. 从 SQLite 收集周期内【已完成】任务（详见第 3 节）
        │     （周期内无完成任务 → 直接报错「该周期内没有已完成任务，暂无法分析」，
        │       前端按钮同步置灰，无法触发）
        ├─ 3. 收集任务清单涉及项目的简报（名称 / 是否核心 / 简介）
        ├─ 4. 构造 user 上下文（Markdown 文本，模板见第 5 节）
        ├─ 5. POST {base_url}/chat/completions
        │     body: { model, messages: [system, user], stream: false }
        │     认证: Bearer {api_key}；超时 90 秒
        │     未设置 temperature / max_tokens 等任何其他参数（全部使用服务端默认）
        ├─ 6. 错误分类（不写入任何结果）：
        │     401 → 「API Key 无效」；402 → 「余额不足」；
        │     其他 HTTP 错误 → 附前 200 字响应体；响应解析失败 → 「AI 返回格式异常」
        └─ 7. 保存结果
              ├─ 周期分析 → analysis_reports 表（type + period_key 唯一，覆盖式写入）
              └─ 项目复盘 → 落盘 logs/{project_id}/{日期}.md + ai_logs 表索引（同日覆盖）
```

## 2. 触发入口与结果生命周期

| 入口 | 位置 | 保存方式 | 覆盖/清空语义 |
|---|---|---|---|
| 今日分析 | 分析页「生成分析」 | analysis_reports (today, 日期键) | 再次分析覆盖 |
| 昨日复盘 | 分析页「生成分析」 | analysis_reports (yesterday, 日期键) | 跨天自然失效（旧记录不再展示） |
| 本周分析 | 分析页「生成分析」 | analysis_reports (week, ISO 周键) | 再次分析覆盖 |
| 上周复盘 | 分析页「生成分析」 | analysis_reports (last_week, ISO 周键) | 跨周自然失效 |
| 项目复盘 | 项目详情页「生成/覆盖今日复盘」 | `logs/{project_id}/{日期}.md` 文件 + ai_logs 索引 | 同日覆盖文件 |

周期键规则：日键 `YYYY-MM-DD`；周键 `YYYY-Www`（ISO 周，周一为一周起点）。

## 3. 发送给 AI 的上下文包含什么、不包含什么

### 3.1 周期分析（今日/昨日/本周/上周）

**任务清单**（每个任务）：

| 字段 | 说明 |
|---|---|
| 任务名称 | 必含 |
| 所属项目 | 必含（`[项目名]` 前缀） |
| 任务描述 | 有则附加（`描述：xxx` 行），为空则省略 |
| 折算工时 | 必含，**由实际得分预先折算**（1 分 = 1 分钟，8 小时 = 1 天，如「1小时40分」） |
| 原始分数 / 价值档位 | **不发送**（工时已含价值加权，减少 AI 负担） |
| 完成时间 / 录入时间 | **不发送**（无分析必要） |

**项目情报**（任务清单涉及的项目，每个项目）：

| 字段 | 说明 |
|---|---|
| 项目名称 | 必含 |
| 是否核心项目 | 必含（「核心项目 / 普通项目」） |
| 项目简介 | 必含（无简介时标注「（无简介）」） |

**数据收集逻辑**：SQL 取全部已完成任务（`status='done' AND completed_at IS NOT NULL`，JOIN 项目表），
Rust 侧按 `completed_at` 日期落在周期内过滤，按完成时间倒序（供界面展示）；
**发送给 AI 前翻转**为完成时间正序（从早到晚），让 AI 按实际执行顺序复盘。

### 3.2 项目复盘

- 项目总分 + 该项目**最近 20 条**完成记录（名称、价值档位、原始分→实际分）
- 记录发送给 AI 前同样**按完成时间正序**（从早到晚）；SQL 取数仍为最新 20 条在前，翻转后早完成者在前
- 未变（本次优化范围是周期分析，项目复盘仅提示词补充了产品理念与结尾鼓励）

### 3.3 当前上下文【仍不包含】的信息（潜在改善点）

| 缺失信息 | 现状 |
|---|---|
| 未完成（待办）任务列表 | 不发送 |
| 历史周期对比（上周/上月数据、趋势） | 不发送 |
| 完成时间的时刻分布（上午/下午/深夜） | 不发送 |
| 连续工作天数、单日最大/最小工时 | 不发送 |
| 项目优先级/手动排序位置 | 不发送 |

## 4. 请求参数（chat/completions）

| 参数 | 值 |
|---|---|
| model | 设置页配置，默认 `deepseek-chat` |
| messages | `[system, user]` 两条 |
| stream | `false` |
| temperature 等 | **未设置**（服务端默认，deepseek-chat 默认 temperature=1.0） |
| 超时 | 90 秒（reqwest 客户端级） |
| 响应解析 | 取 `choices[0].message.content`，空内容视为格式异常 |

## 5. 提示词原文（与代码完全一致）

### 5.1 System Prompt —— 周期分析（今日/昨日/本周/上周）

```
你是「成迹 DoneTrace」的 AI 复盘助手。

成迹 DoneTrace 是一款个人成果记录工具，核心理念是：记录完成、让用户看清自己的来时路、增强自信；并协助用户定期复盘、发现问题。它适用于独立开发者、上班族等脑力工作者，并认为「投入了时间但暂无直接产出」的任务同样值得记录与肯定。

你会收到用户的本期成果记录，包含：
- 任务清单：任务名称、所属项目、任务描述、折算工时（工时已按 1 天 = 8 小时、并结合任务价值加权折算好）；
- 项目情报：项目名称、是否核心项目、项目简介。

重要：工时单位说明——记录中的「1 天」代表 8 个工时，不是自然日的 24 小时。例如「1天2小时30分」= 8 + 2.5 = 10.5 个工时。解读任何天数时请始终按 1 天 = 8 小时换算，不要把它理解成 24 小时。

请基于上述情报：
1. 给出本期分析结论（完成了什么、时间投入的结构如何）；
2. 尝试给出 1-3 条建设性、具体可执行的建议；
3. 语气鼓励但直率，像一个懂行的朋友；
4. 在结尾给予正向鼓励，肯定用户本期的投入；
5. 全文不超过 500 字，使用 Markdown 格式；
6. 尊重「投入了时间但暂无直接产出」的任务，不要否定它们的价值；
7. 始终使用中文回复，即使任务名称或描述中包含其他语言。
```

> 英文界面使用等价的英文提示词（`SYSTEM_PROMPT_PERIOD_EN`），结构一致，并明确要求
> 「Reply entirely in English, even if task names, descriptions, or project names appear
> in other languages.」——保证任务内容为中文时 AI 仍以英文回复。

### 5.2 System Prompt —— 项目复盘

```
你是「成迹 DoneTrace」的个人复盘教练，用户会把他的项目成果记录交给你分析。

成迹 DoneTrace 是一款个人成果记录工具，核心理念是：记录完成、让用户看清自己的来时路、增强自信；并协助用户定期复盘、发现问题。它认为「投入了时间但暂无直接产出」的任务同样值得记录与肯定。

要求：
1. 语气鼓励但直率，像一个懂行的朋友；
2. 输出三个部分：①本期亮点 ②发现的问题/风险 ③对下一周期的 1-3 条具体可执行建议；
3. 全文不超过 500 字，使用 Markdown 格式；
4. 在结尾给予正向鼓励；
5. 始终使用中文回复，即使任务名称或描述中包含其他语言。
```

> 英文界面使用等价英文提示词（`SYSTEM_PROMPT_PROJECT_EN`），同样明确要求以英文回复。

### 5.3 周期分析的 User 上下文模板

```
# {今日|昨日|本周|上周} 成果记录（{周期键}）

## 总览
- 完成任务：{N} 个
- 累计工时：{折算工时，如 1天2小时5分}

## 项目情报
- {项目名}（{核心项目|普通项目}）：{项目简介，无则为「（无简介）」}
- ...

## 任务清单
1. [{项目名}] {任务名称}（工时 {折算工时}）
   描述：{任务描述，无描述则省略此行}
2. ...
```

> 任务清单按**完成时间正序**（从早到晚）编号，编号顺序即用户本期的实际执行顺序。

示例（假设数据）：

```
# 今日 成果记录（2026-10-24）

## 总览
- 完成任务：3 个
- 累计工时：2小时40分

## 项目情报
- DoneTrace（核心项目）：个人成果记录工具的开发
- 学习（普通项目）：（无简介）

## 任务清单
1. [DoneTrace] 完成核心项目功能（工时 1小时40分）
   描述：唯一标记 + 列表置顶 + 迁移 V4
2. [DoneTrace] 修复图标裁剪 bug（工时 40分）
3. [学习] 阅读 Rust 异步编程（工时 20分）
```

### 5.4 项目复盘的 User 上下文模板

```
# 项目「{项目名}」复盘（{今日日期}）

## 总览
- 项目总分：{总分}
- 最近完成记录（近 20 条）：{N} 条

- ...
```

> 记录同样按**完成时间正序**（从早到晚）排列。

## 6. 分数与价值体系

产品内部规则（`src-tauri/src/scoring.rs` / `src/lib/scoring.ts`）：

| 项 | 规则 |
|---|---|
| 任务价值三档 | 常规 ×1.0 / 重要 ×1.5 / 关键 ×2.0 |
| 实际得分 | 任务分数（用户主观输入的投入估算）× 价值系数 |
| 产品内工时换算 | 1 分 = 1 分钟；8 小时 = 1 天（界面「累计工时」与 AI 上下文同源，Rust 权威实现 `fmt_work_hours`） |
| 统计口径 | 只统计已完成任务 |

优化后，AI 收到的工时是已加权折算好的（如「1小时40分」），提示词中已明确
「1 天 = 8 小时、结合任务价值加权折算」，并额外强调「1 天 ≠ 24 小时」（避免工时超过
1 天时模型按自然日理解），AI 不再需要理解原始分数语义。

## 7. 优化方案落实情况与剩余可改善方向

### 7.1 已落实（2026-10-24）

1. ✅ 周期内无已完成任务 → 无法触发 AI 分析（前端按钮置灰 + 后端 EmptyPeriod 报错）
2. ✅ System Prompt 注入产品设计理念（记录完成、增强自信、协助复盘、肯定无产出投入）
3. ✅ 任务清单按新格式：名称 / 所属项目 / 描述 / 折算工时；不发送完成时间与原始分数
4. ✅ 新增「项目情报」：名称 / 是否核心 / 简介
5. ✅ 输出要求：分析结论 + 建设性建议 + 结尾正向鼓励

### 7.2 已落实（2026-10-30）

1. ✅ **回复语言锁定**：中/英提示词均明确要求以对应语言回复（即使任务名称/描述为其他语言），解决英文界面 AI 返回中文的问题
2. ✅ **任务清单正序**：周期分析与项目复盘的完成记录发送给 AI 前均按完成时间正序（从早到晚），AI 按实际执行顺序复盘（界面展示顺序不变）

### 7.3 剩余可改善方向（未实现）

1. **历史对比**：本期 vs 上一周期（工时、任务数、项目分布），无法输出趋势类洞察；
2. **待办信息**：AI 看不到「还剩什么」，难以给出针对性建议；
3. **temperature 未设置**（deepseek-chat 默认 1.0 偏发散，复盘场景或可调低）；
4. **项目复盘记录截断**：只取最近 20 条完成记录，长期项目丢失早期上下文；
5. **500 字上限**：对周复盘可能偏短，且未提供「超限时优先保留什么」的指令。
